# [회의록 #01] 치이카와 수박게임 리부트: 시장조사·세계관·기술·아트 기획 토론

- **일시**: 2026-11-13
- **참석자**: 안티(Antigravity, 팀장), 클로드(Claude Code), 코덱스(Codex)
- **안건**: 기존 웹 원형 수박게임을 Godot/Unity 기반 비정형(캐릭터 실루엣) 물리 퍼즐 실행 프로그램으로 발전시키기 위한 시장·세계관·기술·아트 리서치 및 토론

## 1. 시장조사 및 수요 분석 (안티 조사)

### 1.1 수박게임(Suika Game) 성공 요인
1. **비정형/물리 기반 예측 불가능성**: 격자(Grid) 퍼즐과 달리 물리 엔진의 굴러감, 반동, 일명 '억까' 현상이 도파민과 리플레이 욕구를 자극함.
2. **직관적 규칙 (Easy to Learn, Hard to Master)**: 3초 만에 이해 가능한 규칙 + 크기별 배치 전략의 깊이.
3. **시청각적 ASMR 피드백**: 부딪힘·합체 효과음과 귀여운 비주얼이 캐주얼 유저층에 강하게 어필.
4. **스트리밍/숏폼 바이럴 최적화**: 아슬아슬한 물리 연출과 리액션이 유튜브·트위치·틱톡 등 방송 콘텐츠에 최적화됨.

### 1.2 치이카와(ちいかわ) 세계관 및 IP 조사
1. **세계관 핵심**: 겉보기엔 귀엽고 아기자기하지만, 실제로는 풀 뽑기·토벌 등 일용직 노동과 제초 검정 자격증 시험을 치르는 **현실적이고 다크한 반전 세계관**.
2. **주요 캐릭터**: 치이카와(겁 많지만 노력파), 하치와레(밝고 다정한 소통가, 기타 연주), 우사기(마이웨이·고전투력·특유 추임새), 모몽가, 밤만쥬, 랏코, 갑옷 씨 등.
3. **2차 창작 게임 주의사항 (매우 중요)**:
   - **비영리 원칙**: 공식 허락 없는 상업적 이용(유료 판매, 광고, 후원 링크 등) 절대 금지. 무료 팬 게임으로만 배포 가능.
   - **공식 오인 금지**: 공식 로고/폰트 무단 도용 금지, 타이틀/설명란에 **"비영리 팬 메이드 게임"** 면책 문구 명시 필수.
   - **원작 훼손 자제**: 지나친 고어·폭력·성인 요소 배제.

## 2. 기술/엔진 및 기존 코드 분석 (클로드 보고)

### 2.1 기존 `index.html` 현황
- 단일 파일(9KB), 순수 Canvas + JS 자체 물리.
- 11단계 캐릭터(`img/h, g, i, e, f, d, j, b, a, c, k.svg`), 반지름 `RAD=17~118` **원형 충돌만 사용**.
- 400×640 컨테이너, 중력 `0.35`, 서브스텝 `4`, 질량 `r^2`, 접선마찰 회전.
- 시작 드롭 0~4단계 랜덤, 게임오버 = TOP 라인(`y=110`) 위 정지 2초, 최고점수 `localStorage` 저장.
- **결론**: 원-원 충돌(`O(n^2)`) 구조라 다각형 충돌/각운동량 관성이 없으므로 비정형 물리 게임으로 가려면 사실상 재작성 필요.

### 2.2 엔진 비교: Godot 4 2D vs Unity 2D
- **Godot 4 2D (클로드 추천)**:
  - **장점**: 가볍고(실행파일 30~50MB, 무료/MIT) Windows/웹 export 용이. `Sprite2D -> Create CollisionPolygon2D`로 비트맵 외곽 자동 추출 가능. GDScript가 JS와 유사해 학습·AI 협업이 빠르고, 텍스트 기반 `.tscn`이라 Git diff/PR 충돌이 적음.
  - **단점**: Godot Physics는 볼록 다각형만 허용(오목은 자동 분해), 다수 RigidBody 안정성은 Box2D 대비 약간 떨어질 수 있음.
- **Unity 2D**:
  - **장점**: Box2D 기반 `PolygonCollider2D`, 물리 안정성·에셋 풍부, 모바일 빌드 성숙.
  - **단점**: 에디터 무겁고 빌드 용량 큼, 라이선스/약관 이슈, 바이너리 에셋·`Library` 폴더로 Git 병합 충돌 잦음, AI 자동화 어려움.

### 2.3 비정형 물리 재미요소 및 리스크 대응
- **재미요소**: 캐릭터별 다른 구르기·걸림·쌓임(귀 위에 올라타기, 균형잡기), 모양 맞물림으로 인한 연쇄 합체 예측 난이도, 캐릭터 개성의 물리화.
- **기술 리스크 & 해법**:
  1. **끼임/지터**: 콜라이더를 원본 실루엣보다 단순화(점 8~16개 볼록 분해), 둥근 모서리/마진, 슬립 허용.
  2. **튕김/터널링**: CCD(연속충돌) 활성화, 최대속도 제한, 얇은 돌기는 콜라이더에서 제외.
  3. **무게중심**: 질량/COM/관성 직접 지정 또는 면적 기반 계산(둥근 코어 + 장식 돌기 방식도 대안).
  4. **합체 판정/겹침 폭발**: 최소 접촉 길이/시간 기준으로 스치기 오작동 방지, 합체 직후 스케일업 동안 충돌 약화/푸시.
  5. **게임오버/밸런스**: 라인 위 체류시간 + 슬립 상태 활용, 단계별 면적비/밀도/마찰/반발 테이블화.
- **제안 순서**: 3~4개 캐릭터로 Godot 프로토타입 → 끼임/지터 테스트 → 전체 11단계 확장 (외곽 자동 추출 Python 스크립트는 클로드 담당 가능).

## 3. 에셋/아트/사운드/연출 분석 (코덱스 보고)

### 3.1 기존 에셋 현황
- `img/a.png ~ j.png`: 256×256 RGBA이지만, 단체 일러스트를 **원형으로 자른 초상**이라 알파 외곽을 그대로 충돌체로 따면 다시 원형이 됨. **온전한 몸통·귀·꼬리 전신 실루엣 에셋 재제작 필요**.
- `캐릭 10종.webp`: 1000×941 불투명 단체 일러스트(겹침 때문에 단순 배경제거로 분리 불가).
- `11번째 캐릭터.svg` / `img/k.svg`: SHA-256 동일 중복 파일. 표정/리깅 원본 아님.
- 별도 오디오·영상·표정 시트·엔진 프로젝트 파일 없음.

### 3.2 비정형 캐릭터 연출 및 사운드 제안
- **재미의 중심**: 긴 귀가 눕혀지며 공간 생성, 넓은 몸 받침, 비대칭 몸의 기울어짐 등 형태만 보고 무게중심·안정성을 짐작할 수 있는 물리 퍼즐.
- **표정/스쿼시**: 평상시/낙하 놀람/강한 착지 찡그림/합체 기쁨 4상태 우선 제작. 초기에는 강체 충돌체를 유지하고 그림만 접촉 방향으로 스쿼시 변형.
- **사운드**: 약한 톡/강한 퐁 접촉음(동시 재생 제한), 연쇄 합체 시 음계 상승 효과음, 장난감 악기 계열 루프 BGM.
- **제작 우선순위**: 둥근 몸 / 긴 귀 / 넓거나 비대칭 몸 **대표 3종 전신 투명 에셋**을 먼저 제작해 쌓기·회전·합체 가독성을 검증한 뒤 11단계로 확장.
